# A* 算法作业：原理、Python 实现与对比实验

> 面向《人工智能导论》课程作业：**迷宫寻路** + **八数码**两个经典问题，
> 包含通用 A* 框架、可视化、可复现实验、单元测试和中文报告模板。

## 0. 一句话版本

A* 是一种**启发式图搜索算法**：它用 `f(n) = g(n) + h(n)` 给待扩展节点排序，
其中 `g(n)` 是起点到 `n` 的已花代价，`h(n)` 是对 `n` 到终点剩余代价的估计。
只要 `h` 不高估真实剩余代价（可采纳），A* 就一定能找到最优路径；
`h` 越接近真实值，A* 需要扩展的节点越少。

## 1. A* 是什么

### 1.1 三种搜索的直觉对比

| 算法 | 排序依据 | 特点 |
|---|---|---|
| Dijkstra / 一致代价搜索 | `g(n)` | 像水波一样均匀向外扩展，保证最优，但盲目 |
| 贪心最佳优先搜索 | `h(n)` | 只盯着目标跑，快，但容易钻进死胡同，不保证最优 |
| **A\*** | `g(n) + h(n)` | 兼顾“已经走了多远”和“看起来还有多远”，既最优又高效 |

可以把 `g` 想成导航里的“已行驶里程”，`h` 想成“到终点还剩多少公里”的估计。
A* 每次优先处理“总路程估计最小”的节点。

### 1.2 算法流程

```
OPEN   ← 优先队列（最小堆），按 f 排序；放入起点，g(起点) = 0
CLOSED ← 已扩展节点集合
parent ← 记录每个节点的前驱，用于回溯路径

while OPEN 非空:
    n ← 弹出 f 最小的节点
    if n 是目标节点:
        沿 parent 回溯，返回路径
    for (m, c) in n 的所有后继:          # c 是 n → m 的单步代价
        tentative_g ← g(n) + c
        if tentative_g < g(m):           # 找到更便宜的走法
            g(m) ← tentative_g
            parent(m) ← n
            把 m 压入 OPEN（或降低 m 的优先级）
返回“无解”
```

两个容易写错的细节：

1. **过期节点**：同一个状态可能被多次压入堆中。弹出时若 `g` 值已不是最新的，直接跳过。
2. **是否重新展开**：若 `h` 只可采纳但不一致，一个节点被扩展后仍可能发现更短的路径。
   本实现不使用“硬性 CLOSED 屏蔽”，只要发现更小的 `g` 就重新入队，因此对可采纳启发式仍最优。

### 1.3 为什么 A* 最优

设最优路径代价为 `C*`。若 `h` 可采纳（对所有 `n` 有 `h(n) ≤ h*(n)`），
则对最优路径上的任意节点 `n`：

```
f(n) = g(n) + h(n) ≤ g(n) + h*(n) = C*
```

假设 A* 第一次弹出的目标是次优目标 `G₂`，且 `g(G₂) > C*`。
此时最优路径上必有一个节点 `n` 还在 OPEN 中（或已被扩展），
其 `f(n) ≤ C* < g(G₂) = f(G₂)`，于是 `n` 应该比 `G₂` 先被弹出，矛盾。
因此第一次弹出目标时得到的路径就是最优的。

- **一致性**（`h(n) ≤ c(n,m) + h(m)`）比可采纳性更强：它保证每个节点最多扩展一次，
  配合普通的 CLOSED 表即可，不需要重新展开。
- 常见的曼哈顿距离、错位方块数、迷宫直线距离都满足一致性。

### 1.4 复杂度

| 指标 | 最坏情况 | 说明 |
|---|---|---|
| 时间 | `O(b^d)` | `b` 为分支因子，`d` 为解深度；启发式越好，实际远小于这个上界 |
| 空间 | `O(b^d)` | 需要保存 OPEN/CLOSED，是 A* 的主要瓶颈 |
| 最优性 | 是 | `h` 可采纳 + 允许重新展开（或 `h` 一致） |
| 完备性 | 是 | 分支有限、单步代价为正时 |

更精确地说，A* 会扩展所有 `f(n) < C*` 的节点，并可能扩展一部分 `f(n) = C*` 的节点；
`h` 越“紧”，满足 `f(n) < C*` 的区域越小。

### 1.5 常见变体

- **加权 A\***：`f = g + w·h (w > 1)`，更快，但代价不超过最优解的 `w` 倍（当 `h` 可采纳时）；
- **贪心最佳优先**：`f = h`，即 `w → ∞` 的极端情况；
- **IDA\***：迭代加深 + 阈值，把空间降到 `O(d)`，适合内存受限场景；
- **双向 A\***、**D\* Lite**：分别用于大规模图与动态环境。

## 2. 两个问题的建模

| | 八数码 | 迷宫 |
|---|---|---|
| 状态 | 长度 9 的元组，`0` 表示空格 | 当前格子 `(row, col)` |
| 动作 | 空格与上下左右方块交换 | 上下左右（可选八个方向） |
| 单步代价 | 1 | 1（对角线 `√2`） |
| 目标测试 | 等于 `(1,2,3,4,5,6,7,8,0)` | 到达 `goal` |
| 启发式 | 错位方块数 / 曼哈顿距离 / 线性冲突 | 曼哈顿距离 / octile 距离 |

### 2.1 八数码

**可解性**：3×3 拼图忽略空格后的逆序数，若起点与目标奇偶性相同则可解。
本项目的 `random_instance` 从目标状态随机游走生成实例，因此一定可解；
`is_solvable()` 可用于检查老师给的任意初始状态。

**曼哈顿距离的可采纳性**：一次移动只让一个方块移动一格，该方块的曼哈顿距离最多变化 1，
所以“剩余步数 ≥ 所有方块曼哈顿距离之和”，即 `h ≤ h*`。
同理，一次移动最多让一个错位方块归位，所以错位数也可采纳。
线性冲突在曼哈顿距离上进一步加上“同一行/列中顺序颠倒的方块对”的 2 步惩罚，
仍然不高估真实代价。

### 2.2 迷宫

四方向移动时，每一步最多让曼哈顿距离减少 1，所以曼哈顿距离可采纳。
允许对角线时，一步最多让 octile 距离减少 `√2`（对角线）或 1（直走），
因此 `h = (dr+dc) + (√2−2)·min(dr,dc)` 也可采纳。
代码禁止“穿墙角”：对角线移动要求两个相邻直角格子都可走。

> 小提示：完美迷宫（只有唯一通路）对曼哈顿启发式很不友好，A* 的优势不明显；
> 带环路、较开阔的迷宫更能体现启发式的作用。项目的 `loop_rate` 参数控制这一点。

## 5. 实验结果

> 数据由 `python3 experiments.py` 在本机生成，完整表格见
> [`results/experiment_results.md`](results/experiment_results.md)。
> 不同机器上的**耗时**会变，但**扩展节点数**是可复现的。

### 5.1 八数码：启发式越强，扩展越少

20 个随机实例（从目标随机游走 24 步），评价函数 `f = g + h`：

| 启发式 h(n) | 平均扩展节点 | 最大扩展节点 | 平均耗时 (ms) | 平均路径代价 | 次优解 |
|---|---|---|---|---|---|
| h=0（退化为 Dijkstra/BFS） | 38 685.8 | 137 206 | ≈111 | 18.00 | 0/20 |
| 错位方块数 | 2 565.4 | 13 659 | ≈10.3 | 18.00 | 0/20 |
| 曼哈顿距离 | 224.7 | 682 | ≈0.97 | 18.00 | 0/20 |
| 曼哈顿 + 线性冲突 | 130.8 | 405 | ≈1.27 | 18.00 | 0/20 |

四者的路径代价完全相同（都是最优解），但扩展节点数相差近 **300 倍**。
这说明 A* 的效率几乎完全取决于启发式的“信息量”。

![八数码不同启发式的扩展节点数](figures/puzzle_heuristics.png)

### 5.2 加权 A*：速度与最优性的权衡

| 权重 w | 平均扩展节点 | 平均路径代价 | 次优解 |
|---|---|---|---|
| 1.0 | 224.7 | 18.00 | 0/20 |
| 1.25 | 221.2 | 18.00 | 0/20 |
| 1.5 | 187.6 | 18.40 | 3/20 |
| 1.75 | 156.3 | 18.50 | 4/20 |
| 2.0 | 150.3 | 18.80 | 6/20 |

`w` 增大后扩展节点减少约 33%，但开始出现次优解，路径平均变长。
这就是“更快但可能不最优”的加权 A*。

![加权 A* 权衡](figures/weighted_astar.png)

### 5.3 迷宫：A* vs Dijkstra vs 贪心

25×25 随机迷宫（额外打通 30% 的墙，形成环路），4 个迷宫取平均：

| 算法 | 平均扩展节点 | 平均路径代价 | 找到解 | 最优解 |
|---|---|---|---|---|
| Dijkstra（h=0） | 354.8 | 46.25 | 4/4 | 4/4 |
| 贪心最佳优先（只看 h） | 73.0 | 50.75 | 4/4 | 1/4 |
| **A\*（h=曼哈顿）** | **112.0** | **46.25** | **4/4** | **4/4** |

A* 的扩展节点数只有 Dijkstra 的约 **1/3**，却和 Dijkstra 一样最优；
贪心扩展最少，但 4 个迷宫只有 1 个得到最优路径。

## 6. 怎么写作业报告

仓库提供了 [`实验报告模板.md`](实验报告模板.md)，已经写好算法原理、
启发式设计与实验表格的骨架。建议按下面的顺序补充：

1. **问题描述**：状态、动作、代价、目标测试分别是什么；
2. **算法原理**：写出 `f = g + h`、伪代码，并证明“可采纳 ⇒ 最优”；
3. **启发式设计**：说明你是怎么想到 `h` 的，并证明它不高估；
4. **实现细节**：优先队列、重复状态处理、路径回溯、可解性判断；
5. **实验**：至少比较两种启发式，报告扩展节点数、路径代价、运行时间；
6. **分析**：不要只贴表格，要解释“为什么 h 更强就更快”“为什么贪心会次优”；
7. **复杂度与局限**：A* 的空间开销、启发式设计成本、加权 A* 的取舍。

### 常见扣分点

- 八数码不判断可解性，对无解状态死等；
- 启发式乘了系数（如 `2 × Manhattan`）却仍声称最优；
- 用 CLOSED 表直接丢弃重复节点，遇到不一致启发式时返回次优解；
- 目标测试放在“生成时”而不是“弹出时”，在加权 A* 下容易提前返回次优解；
- 只比较运行时间，不比较扩展节点数（时间受机器影响大）；
- 路径回溯方向写反，或忘记把起点加入路径。

## 9. FAQ

**Q：为什么我的 A* 还不如 Dijkstra？**
A：检查 `h` 是否写错、是否用了 `closed` 表且不重新展开、是否把 `h` 加到了 `g` 上却忘了排序。
另外，完美迷宫中曼哈顿启发式信息量很低，A* 接近 Dijkstra 是正常的。

**Q：八数码无解怎么办？**
A：先算逆序数奇偶性；无解时直接报告，不要盲目搜索。本项目 `is_solvable()` 可直接用。

**Q：可以只交一个问题的代码吗？**
A：可以。`astar.py` 与具体问题解耦，删掉不用的 `problems/*.py` 和对应 demo 即可。

**Q：老师要求单文件提交怎么办？**
A：把 `astar.py` 的核心函数与 `problems/eight_puzzle.py`（或 `problems/maze.py`）的类复制到同一个 `.py` 即可，
二者没有循环依赖。

**Q：老师要求 C++ 怎么办？**
A：算法逻辑完全一致：`priority_queue` 存 `(f, g, state)`，`unordered_map` 存 `g` 和 `parent`。
注意 C++ 的 `priority_queue` 是最大堆，需要自定义比较器或存负值。
